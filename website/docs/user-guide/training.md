# 学習の実行

## 条件を指定して実行する

`config/mnist_lgn.json` をエディタで開き、未使用の名前でコピーを保存します。例えば `config/experiment.json` を作成し、学習回数を変更する場合は、その中の `train.epochs` を編集します。

| 変更したい条件 | 編集する項目 |
|---|---|
| 学習回数 | `train.epochs` |
| バッチサイズ | `data.batch_size` |
| 初期学習率 | `train.optimizer.learning_rate` |
| 乱数の初期値 | `run.seed` |
| 出力先の親フォルダ | `run.log_dir` |
| 学習後に回路を出力するか | `circuit.enabled` |

例えば10 epochを実行する場合は `train.epochs` を `10` に設定し、次のコマンドを実行します。他の設定項目もすべて残してください。

```shell
python main.py --config config/experiment.json
```

`python main.py` だけで起動した場合は通常設定を使用します。配布時の通常設定は100 epoch、回路出力有効です。

## CPUとGPUを選択する

| `run.device` | 動作 |
|---|---|
| `"cpu"` | CPUで実行する |
| `"cuda"` | 利用中のPyTorch環境からCUDAを使用する。利用できない場合はエラー |
| `"auto"` | CUDAを利用できればGPU、それ以外はCPUを使用する |

CUDAを使用する前に、学習に使う仮想環境を有効化して確認します。

```shell
python -c "import torch; print(torch.__version__); print(torch.cuda.is_available())"
```

最後の行が `True` であれば、そのPythonからCUDAを利用できます。`False` の場合は、使用中の仮想環境、PyTorchの種類、GPUドライバを確認します。[環境構築](../startup/setup.md)のCPU用インストール手順を、既に動作するGPU環境に適用しないでください。

対応範囲は単一CPUまたは単一CUDA GPUです。複数GPUでの並列学習、分散実行、AppleのMPSを選ぶ設定はありません。

## 学習と評価の順序

1. 設定とデバイスを確認し、実行ごとの保存先を作成します。
2. 取得済みデータとモデルを読み込みます。初期重みを指定していれば適用します。
3. 1 epochの学習後、検証用データ全体を評価します。
4. 検証精度がそれまでの最高値を上回った場合にbestを保存し、履歴・グラフ・端末表示を更新します。
5. 学習率を更新し、指定したepoch数まで繰り返します。
6. finalを保存した後、保存済みbestを読み込み、テスト用データ全体を一度評価します。
7. 有効な場合はbestを回路へ変換し、最後に「学習完了」を表示します。

検証は毎epoch、テストは学習終了後に一度です。「指定したepoch間隔でテストする」機能や、検証精度に応じた早期終了の設定はありません。

`main.py` は常に学習から開始します。保存済みの重みを指定して「評価だけ」「回路の再出力だけ」を行うCLIはありません。学習を行わず回路を読み込んで使用する方法は、[ライブラリの直接利用](./core-library.md)を参照してください。

## 指標の読み方

epoch行の `train` は学習用データ、`validation` は検証用データの指標です。学習中の指標は各バッチの重み更新前の出力から集計しており、epoch終了後の同一モデルで学習用データを再評価した値ではありません。

論理ゲートNNでは、学習時は勾配を計算できる連続演算、検証・テスト時は選択したゲートによる離散演算を使用します。データの違いに加え、演算方法も異なるため、学習指標と検証指標が一致するとは限りません。

バッチ途中の進捗行は表示しません。各epochの学習・検証と保存が終了してから1行を表示します。1 epochであっても、MNISTの学習50,000件・検証10,000件・最終テスト10,000件を処理します。

## seedを指定して比較する

`run.seed` は乱数生成器の初期化に使用します。MNISTでは学習用・検証用の分割と学習データの順序にも使います。比較実験ではseedだけでなく、データ、モデル構造、ソフトウェアのバージョン、デバイスも揃えてください。

このアプリは決定論的な演算を強制していません。同じseedであっても、環境や演算条件を含めた学習結果の厳密一致は保証しません。実行条件は[ログと成果物](./outputs.md)で確認できます。

## 中断と再実行

Ctrl+Cを押すと中断します。既に保存されたファイルは残りますが、中断時点のモデルを自動でfinalとして保存することはありません。`model_final.pth` や `test_metrics.json` が存在するかどうかは、中断した段階によって異なります。

再実行すると、新しい実行フォルダでepoch 1から開始します。途中までのepochやoptimizer状態を引き継ぐ機能はありません。保存済みの重みを利用したい場合は、[保存済み重みの利用](./checkpoints.md)を参照してください。

詳細な呼び出し順は[学習workflow](../code-reference/utils/trainer/workflow.md)で確認できます。
