# モデル・データセットの追加

学習条件の変更は設定JSONで行いますが、未登録のモデルやデータセットを使うには、その実装を追加して登録する必要があります。

| 追加したい内容 | 主な変更箇所 | 手順 |
|---|---|---|
| モデル構造 | `model/` のモデル定義と `MODEL_REGISTRY` | [モデルの追加](./models.md) |
| データセット | `utils/data/` の読み込み・前処理と `DATASET_REGISTRY` | [データセットの追加](./datasets.md) |
| データ取得方法 | データセット専用の取得関数と `tools/download_dataset.py` の対応表 | [データセットの追加](./datasets.md) |
| アプリから独立した論理NNの利用 | 同梱 `logicNN_core` を使うPythonコード | [ライブラリの直接利用](./core-library.md) |

## モデルとデータセットの組み合わせ

データセットが返す入力形状とクラス数は、モデルが定義する値と一致している必要があります。例えばMNISTのモデルが `[batch, 1, 28, 28]` の画像を受け取る場合、それと異なる形状のデータセットに登録名だけを変更して対応することはできません。

現在の学習アプリは、入力ごとに一つのクラス番号を予測する分類処理です。回帰や複数ラベル分類は、データセットの追加だけでは対応できません。共通の学習処理・評価・保存形式も検討する必要があります。

## 追加後に確認する順序

1. 少数の入力で、前処理後の形状・型・ラベルを確認します。
2. モデル単体で、入力からクラススコアまで計算できることを確認します。
3. 学習と評価の両方を確認してから、アプリに登録します。
4. 少ないepoch数、回路出力無効で学習・保存・重みの再読み込みを確認します。
5. 回路出力が必要な場合は、Pythonで学習できることとは別に、変換可能な演算と二値入力時の出力を確認します。

これは追加実装を行う際の確認手順です。通常の学習起動時に、開発用テストを自動実行する機構を追加するものではありません。
