# エラー対応

## 最初に確認する情報

エラーが発生した場合は、端末に表示されたメッセージ、対象の設定項目やファイル、最後に実行していた処理を確認します。想定したエラーでは `[ERROR]` に続いて詳細と「対応」を表示します。想定外の例外ではPythonのトレースバックが表示されます。

問い合わせる場合は、使用したコマンド、設定JSON、仮想環境のPythonとPyTorchのバージョン、エラー全文、保存先を記録してください。共有前に、個人名などを含むパスや不要な環境情報がないか確認します。

## 起動・設定

| 症状 | 確認と対応 |
|---|---|
| `main.py` が見つからない | プロジェクトルートから実行しているか確認する |
| `logicnn_core` などをimportできない | 仮想環境を有効化し、[環境構築](../startup/setup.md)の手順と使用中のPythonを確認する |
| 「設定ファイルを読み込めません」 | `--config` のパス、ファイルの存在、UTF-8で保存されているかを確認する |
| 「設定ファイルの内容が不正です」 | 指摘された項目の型・値域・必須項目を[設定ファイル](./configuration.md)と照合する |
| 「未登録の名前です」 | モデル・データセット・損失関数・最適化手法・学習率更新方式の登録名を確認する |
| `unrecognized arguments` | `python main.py --help` を確認する。epoch数やデバイスはJSONで指定する |

`python -c "import sys; print(sys.executable)"` で、実際に使用しているPythonを確認できます。設定不正の回避のために未知の項目を無視したり、型のチェックを外したりする必要はありません。

## データ・学習

| 症状 | 確認と対応 |
|---|---|
| 「MNISTデータが見つかりません」 | [データ取得](../startup/dataset.md)を実施し、`data.root` が取得時の `--root` と一致するか確認する |
| 「モデルとデータセットが適合しません」 | 入力形状・クラス数の一致を確認する。バッチサイズは入力形状に含めない |
| 「CUDAを利用できません」 | 使用中の仮想環境とCUDA対応のPyTorchを確認する。CPUを使う場合は `run.device` を `"cpu"` に変更する |
| メモリ不足 | 実行を終了してから `data.batch_size` を小さくして再実行する。必要に応じてモデル構造や他のプロセスの利用状況も確認する |
| 学習開始後、しばらく指標が出ない | バッチ途中の進捗表示はない。epoch全体の学習・検証・保存が終わるまで待つ |
| 正解ラベル・Tensor形状のエラー | 追加したデータ処理が、入力と整数のクラス番号を正しい形状で返すか確認する |
| 損失がNaNまたはInfになる | 一旦中断し、入力、ラベル、学習率、追加したモデルの演算を確認する。異常値のまま結果を比較しない |

MNISTの取得に失敗した場合は、ネットワーク、保存先の書き込み権限、空き容量を確認します。最初から既存の学習ログや重みを削除する必要はありません。

## 保存・評価結果

| 症状 | 確認と対応 |
|---|---|
| チェックポイントの形式・適合性エラー | [保存済み重みの利用](./checkpoints.md)に従い、保存形式・モデル構造・データセット・前処理を照合する |
| `model_final.pth` や `test_metrics.json` がない | エラーや中断が、どの段階で起きたか確認する。中断時のfinal自動保存は行わない |
| グラフの線が見えない | 1 epochだけの場合は正常な場合がある。凡例と `metrics.jsonl` を確認する |
| 画面とJSONで数値が違って見える | 正解率の割合／百分率と、画面表示の丸めを確認する |
| 同じseedでも結果が一致しない | データ、モデル、デバイス、ソフトウェアの条件を比較する。厳密一致は保証していない |
| 保存に失敗する | 対象フォルダの権限、空き容量、他のアプリによるファイルの使用状況を確認する |

## 回路出力・ライブラリの直接利用

| 症状 | 確認と対応 |
|---|---|
| 学習後の回路出力に失敗する | 表示された「段階」と原因を確認し、[回路出力](./circuit.md)の対応範囲と照合する |
| Pythonでは動くモデルを回路化できない | すべてのPyTorch演算が回路変換対象ではない。モデルに追加した演算を確認する |
| Cの実行ができない | ソース生成とコンパイルは別。対応するCコンパイラと、コンパイル結果を確認する |
| コンパイル済み回路を再利用できない | 同じCircuitに対してcompileしたか確認する。簡略化するとコンパイル済み状態は無効になる |
| 回路出力モードのモデルを学習へ戻せない | 直接利用時は `set_export_mode(model, False)` で解除してから `model.train()` を実行する |

回路生成の途中で失敗した場合も、学習済みモデルや、先に生成された回路ファイルは残します。残っているファイルを確認し、部分的な出力と正常完了を区別してください。

## 終了状態

| 終了コード | 意味 |
|---|---|
| `0` | 正常終了。ヘルプ表示も0 |
| `1` | アプリが扱う設定・入出力・回路生成などのエラー |
| `2` | コマンドライン引数の誤り |
| `130` | Ctrl+Cによる利用者の中断 |

未処理の例外はトレースバックも確認してください。終了コード1だけで、原因が想定済みのエラーか未処理例外かを区別することはできません。

エラー時も、変更前の設定や重要な成果物は保持して調査します。詳細な例外処理は[main.pyのコードリファレンス](../code-reference/main.md)を参照してください。
