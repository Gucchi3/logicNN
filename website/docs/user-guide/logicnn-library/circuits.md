# 学習済みモデルから回路へ

学習済みモデルの重みから、使用する論理関数と接続を確定すると、入力ビットから出力ビットを求める回路として表せます。このページでは、`Circuit.from_model()` の内部で何を保存し、簡略化や出力で何を維持するのかを説明します。

APIを動かす完全なコード例は、直前の[ライブラリの直接利用](../core-library.md)を参照してください。

## 1. 何を変換し、何を変換しないか

| 学習・評価モデルにある情報 | 回路での扱い |
|---|---|
| ゲートを学習する重み | 決定済みの真理値表や論理演算に置き換える |
| 入力接続の候補と重み | 評価時に選んだ接続位置に置き換える |
| 各層の形状操作 | どの信号をどこへ渡すかという対応に置き換える |
| `GroupSum` と対応する定数演算 | 集約処理として保持する。CとPython評価が使用する |
| 損失・optimizer・正解ラベル | 予測に不要なので回路に含めない |
| データ取得やファイルからの画像読み込み | 回路の外側で実行する |

`Circuit` は学習済みモデルのコピーから作られる、別のオブジェクトです。生成した回路の値を変更して、元の学習用重みへ自動的に戻す機能はありません。

## 2. モデルから内部表現を作る

`Circuit.from_model(model, input_shape=(4,))` は、おおむね次の順で処理します。

1. モデルの独立コピーを作る。
2. コピーをCPUの評価モードへ移し、回路出力モードにする。
3. バッチ数1のbool入力でPyTorchの処理を追跡し、演算と依存関係を得る。
4. 対応する演算をライブラリ共通の回路データへ変換する。
5. 最終的な数値出力に加え、加算前の論理ビットの対応も保存する。

この追跡にPyTorchのFXを利用します。FXのグラフは、どの演算の結果を次の演算が使うかを表すものです。重みを再学習したり、入力例の正解を覚えたりする処理ではありません。

変換に使う `input_shape` は1標本の形状であり、バッチ数は含めません。`(4,)` は4要素の入力、`(1, 28, 28)` は1チャンネル・縦28・横28の入力です。生成後の回路評価では、先頭にバッチ軸を付けたデータを渡します。

元モデルのデバイス、重み、学習／評価モードはこの変換で変更しません。また、すべてのPyTorch演算が変換できるわけではありません。データに応じてPythonの処理自体を切り替える独自コードや、未対応の演算を使ったモデルは、学習できても回路化できない場合があります。

## 3. 回路データのクラスを読む

学習モデルとC・Verilogの間で共有する形式を**中間表現（IR）**と呼びます。ここではPythonのdataclassで表現しています。

| クラス・項目 | 意味 | 例 |
|---|---|---|
| `Gate` | 1本の論理信号を生成する演算と入力信号ID | 入力ID0と1のANDをID4として保存する |
| `GateOp` | ゲートの演算名 | AND、OR、NOT、定数、配線 |
| `SumReduction` | 複数のビットの和と、その後の数値演算 | 4ビットを加算し、2で割る |
| `ScalarOperation` | 集約後に順番どおり実行する演算 | 加算、除算、型変換 |
| `ScalarConstant` | 演算で使用する定数と型の情報 | Pythonの2.0か、特定dtypeのTensor定数か |
| `TensorDType` | 数値出力の型 | int64、float32など |
| `LogicalOutput` | 1個の最終出力に対応する、加算前ビットの順序付きID列 | あるクラスへ集約する4本の信号 |
| `CircuitData` | 形状・ゲート・集約・出力対応をまとめた回路全体 | JSONへ保存する情報の元になる |
| `FxSignalReference` | 外部FXから構築するときの元信号の位置 | FXノード名と平坦化後の位置 |

信号IDは数値そのものではなく、**値の参照先**です。IDが12の信号でも、その値は0または1です。また、IDの順に並べたものが外部出力の順序とは限りません。

通常の利用では、これらのクラスを手作業で構築する必要はありません。`Circuit.from_model()` で生成し、`to_dict()` やJSONで構造を確認できます。外部FXを受け取る `from_fx_graph()` では、元の論理出力対応を `logical_outputs` として明示する必要があります。

型の全項目は、[回路データ型](/code-reference/utils/logicNN_core/src/logicnn_core/circuit/types)を参照してください。

## 4. 4入力・6入力のLUTを回路へ変換する

多入力LUTにも真理値表があります。変換時には、入力が0の場合と1の場合に分け、各場合の出力を論理演算で選ぶ形へ展開します。

```text
f(x0, 残りの入力)
  = (NOT x0 AND f(0, 残りの入力))
    OR
    (x0 AND f(1, 残りの入力))
```

残りの入力についても同じ分割を繰り返せば、AND・OR・NOTと定数で表せます。真理値表を大きな整数IDにまとめられない場合でも、表そのものがあれば変換できます。そのため6入力で `truth_tables_with_ids()` のIDが `None` でも、回路生成が未対応という意味ではありません。

この処理は、FPGAの物理的な6入力LUTを1個指定する操作ではありません。生成された論理式を対象デバイスへ割り当てる工程は、後段の論理合成ツールが行います。

## 5. 簡略化とは、同じ出力を少ない演算で表すこと

離散化は「学習表現から論理関数を選ぶ処理」、簡略化は「選んだ後の回路を整理する処理」です。簡略化によって再学習や精度の再最適化を行うわけではありません。

| 簡略化前 | 簡略化後 | 理由 |
|---|---|---|
| `x AND 1` | `x` | どちらの入力値でも結果が同じ |
| `x AND 0` | `0` | 出力は必ず0 |
| `x XOR x` | `0` | 同じ値同士なので必ず0 |
| `NOT(NOT x)` | `x` | 二重反転で元に戻る |
| 同じ入力の同じANDが2個 | 1個のAND結果を共有 | 同じ計算を重複して行わない |
| どの出力にも使わないゲート | 削除 | 観測する出力に影響しない |

`circuit.simplify()` は回路オブジェクト自身を更新し、戻り値は `None` です。`circuit = circuit.simplify()` と代入しないでください。すでにCへコンパイルしていた場合、その状態は解除され、再コンパイルが必要になります。

浮動小数点の式は、数学的に等しくても計算順序によって丸め結果が変わる場合があります。そのため、論理式の同値変換と、集約後の数値式の並べ替えは同一の問題ではありません。現在の回路は集約後の数値演算の順序と型も保存します。

## 6. なぜ加算前の出力を保存するのか

2クラスのモデルに、次の生ビットがあるとします。`x` と `y` は入力から計算される信号です。

```text
グループ0: [x, 1, x]
グループ1: [0, y, 1]
```

スコアだけが必要なら、`2*x + 1` と `y + 1` にまとめても値を計算できます。しかし、この2個の式だけでは、元の6個の出力のどの位置が定数で、どの位置が重複していたかを復元できません。

Verilogには、次の6ビットを元の順序のまま出力する必要があります。

```text
logic_output = [x, 1, x, 0, y, 1] という順序の6本の信号
```

上記は順序を示す説明であり、Verilogの連結式ではありません。実際には `logic_output[0]` が先頭の `x` に対応します。

この対応を保存するのが `logical_outputs` です。内部では同じ `x` の計算を共有しても、外部出力の2つの位置を1つに減らしません。定数出力も本数に含めて保持します。

`logical_output_ids()` はこの順序を返しますが、IDをソートしたり、`set` に変換して重複を除去したりしないでください。出力の意味が変わります。

## 7. 何と何を比較すればよいか

| 比較対象 | 比較する値 |
|---|---|
| 評価モードのPyTorchモデルと `Circuit.evaluate()` | 同じ二値入力に対する集約後のスコア |
| Python回路評価とコンパイル済みC | 集約後のスコア |
| `evaluate_logical_outputs()` とVerilog | 加算前の生ビットとその順序 |
| 簡略化前と簡略化後 | スコアだけでなく、生ビットも比較する |

論理ビットと整数の集約値は完全一致を確認できます。浮動小数点のスコアは許容誤差を設けて比較します。学習モードの連続出力を、離散化済み回路の出力と一致させようとしないでください。

次は、[直接利用の例](../core-library.md)で作成した `model` と、二値の `inputs` を使う追加例です。`core_example.py` の `main()` 内で、学習・評価後に同じインデントで追加してください。この断片だけをスクリプト末尾へ貼り付けても、`main()` 内の変数は参照できません。

```python
circuit = Circuit.from_model(model, input_shape=(4,))
before_scores = circuit.evaluate(inputs)
before_bits   = circuit.evaluate_logical_outputs(inputs)

circuit.simplify()
after_scores = circuit.evaluate(inputs)
after_bits   = circuit.evaluate_logical_outputs(inputs)

torch.testing.assert_close(after_scores, before_scores)
assert torch.equal(after_bits, before_bits)
print("簡略化前後でスコアと生ビットが一致しました。")
```

これは例を確認するための比較処理であり、通常の学習バッチごとに実行するものではありません。また、このPython内の比較だけでCコンパイラやVerilogシミュレータを含む全経路を検証したことにはなりません。

## 8. 入出力の境界を守る

CとVerilogは、二値化済み入力を受け取る前提です。元画像の0～255の画素値を入力するインターフェースではありません。前処理の閾値、特徴の順序、入力形状を学習時と一致させてください。

ライブラリの二値化層をモデル内へ置けることと、生成回路が実数画像入力に対応することは別です。現在の回路生成はbool入力でモデルを追跡するため、実数を受け取る前処理回路を自動的に作る機能ではありません。

Cは集約後の値を返しますが、クラス番号を求める `argmax` は別です。Verilogは生ビットを返し、加算・bias・tau・argmax・クロック・リセット・パイプラインレジスタを含みません。ファイル形式とポートの詳細は[回路出力](../circuit.md)を参照してください。

回路変換そのものの実装を読む場合は、[Circuit](/code-reference/utils/logicNN_core/src/logicnn_core/circuit/circuit)、[グラフの変換](/code-reference/utils/logicNN_core/src/logicnn_core/circuit/builder)、[簡略化](/code-reference/utils/logicNN_core/src/logicnn_core/circuit/simplification)の順に進むと、入口と内部処理の関係を追えます。
