# 保存済み重みの利用

logicNNのチェックポイントを、新しい学習の初期重みとして使用できます。これは中断した学習の再開ではなく、保存済みのモデル状態からepoch 1の学習を始める機能です。

## bestとfinalを選ぶ

| ファイル | 保存するモデル | 選ぶ目安 |
|---|---|---|
| `model_best.pth` | 検証精度が最も高かったepoch。同率の場合は先のepochを保持する | 検証結果が最良だった状態を初期値にしたい場合 |
| `model_final.pth` | 最後のepochが終了した状態 | 最後まで学習した状態を初期値にしたい場合 |

両方とも同じlogicNN形式で、どちらも初期重みに指定できます。bestの選択基準は検証精度であり、損失の最小値やテスト精度ではありません。

## 初期重みを指定する

1. 使用するチェックポイントの実際の保存先を確認します。
2. 通常設定を別名で保存し、`run.initial_checkpoint_path` をそのパスに変更します。
3. 今回の学習回数・学習率などを設定して実行します。

以下は `run` 区分を置き換える例です。日時部分は実際の実行フォルダ名に置き換えてください。

```json title="設定JSONのrun区分"
{
  "seed": 0,
  "device": "auto",
  "log_dir": "log",
  "initial_checkpoint_path": "log/20260913_120000/model_best.pth"
}
```

この断片だけを設定ファイル全体として保存することはできません。`run` の中身として使用し、`data`、`model`、`train`、`circuit` も維持します。`config/finetune.json` として保存した場合は次のように実行します。

```shell
python main.py --config config/finetune.json
```

開始時の表で「初期重み」に指定したパスが表示されることを確認してください。新しいランダムな重みで開始する場合は、`initial_checkpoint_path` を `null` に戻します。

## 引き継ぐ情報と引き継がない情報

| 対象 | 新しい学習での扱い |
|---|---|
| モデルの重み・buffer | 保存済みの状態を読み込む |
| epoch番号 | 1から開始する |
| optimizer・scheduler | 今回の設定で新規作成する |
| 学習率 | 今回の初期学習率から開始する |
| bestの選択・履歴・保存先 | 今回の実行で新しく作成する |
| 乱数状態 | チェックポイントからは復元せず、今回のseedで初期化する |

bufferは、固定接続のインデックスなど、学習パラメータ以外にモデルが保持する状態です。

例えば、保存時のepochが50で今回の `train.epochs` が10なら、表示は `Epoch 1/10` から `Epoch 10/10` までになります。51から60へ進むわけではありません。

## 読み込みの条件

- logicNNが保存した `model_best.pth` または `model_final.pth` を使用します。
- モデル名、入力形状、クラス数、`architecture_info()` の構造情報が現在のモデルと一致する必要があります。
- データセット名、入力形状、クラス数、前処理の情報が一致する必要があります。
- モデルの重みのキーと形状が適合する必要があります。

モデル構造をJSONから自動で作り直す機能ではありません。保存済みの構造情報は、現在のモデル定義との照合に使います。層の幅やゲートの入力数を変更したモデルに、変更前の重みを部分的に読み込む機能もありません。

一方、今回の学習回数・学習率・バッチサイズ・seedなどは変更できます。ただし条件を変えた実験として扱い、前回の途中から連続した学習と混同しないでください。

旧 `logicnn` やtorchlogixの保存形式、任意の `state_dict` を自動で変換する互換機能はありません。出所が不明なチェックポイントは読み込まないでください。

読み込み時の詳細は[チェックポイント処理](../code-reference/utils/results/checkpoint.md)、適合性の確認は[学習workflow](../code-reference/utils/trainer/workflow.md)を参照してください。
