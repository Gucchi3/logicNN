# 回路出力

学習した論理ゲートNNを、学習用の重みを持たない回路へ変換できます。通常の `main.py` では、学習後のbestモデルから簡略化済みの回路を作り、JSON・C・Verilogの3形式をまとめて保存します。

このページでは通常の学習実行に組み込まれた出力方法を説明します。小さなモデルを自分で組み立てて回路化する方法は、[ライブラリの直接利用](./core-library.md)を参照してください。

## 1. 回路出力を有効にする

使用する設定JSONの `circuit.enabled` を `true` にします。

```json title="設定JSONのcircuit部分"
{
  "circuit": {
    "enabled": true
  }
}
```

上記は設定の一部分です。ほかの項目を削除せず、設定JSON全体を保存してください。有効化した仮想環境で、プロジェクトルートから実行します。

```shell
python main.py --config config/mnist_lgn.json
```

配布時の `config/mnist_lgn.json` は回路出力が有効です。このコマンドは回路変換だけでなく、設定されたepoch数の学習から実行します。既存のチェックポイントを指定した場合も、学習を省略する動作にはなりません。

`false` にすると、学習・検証・チェックポイント保存・最終テストは実行し、回路の生成と保存だけを省きます。通常の設定には、簡略化・JSON・C・Verilogを個別に切り替える項目はありません。

## 2. 生成の流れと保存先

通常の実行では、次の順に処理します。

1. 全epochの学習と検証を終了し、`model_final.pth` を保存する。
2. 保存済みの `model_best.pth` を読み戻し、テスト用データを評価する。
3. bestモデルの独立したCPU評価用コピーから、二値入力を扱う回路を生成する。
4. 定数の計算や不要な配線・重複した論理演算の整理により、回路を簡略化する。
5. JSON、C、Verilogを順に保存する。

回路化によって元モデルの重みや実行デバイスは変更しません。学習をGPUで行った場合も、この回路変換はCPU側で行います。

```text
log/YYYYMMDD_HHMMSS/
└── circuit/
    ├── circuit_simplified.json
    ├── circuit.c
    └── circuit.v
```

3ファイルの役割は次のとおりです。

| ファイル | 内容 | 主な用途 |
|---|---|---|
| `circuit_simplified.json` | 論理ゲート、信号の接続、集約後の数値演算、元の生ビットとの対応 | 回路の保存・再読込・Pythonでの評価 |
| `circuit.c` | 二値入力から集約後の値まで計算するC関数 | Cプログラムへの組み込み、コンパイル後のCPU実行 |
| `circuit.v` | 二値入力から集約前の生ビットを出力する組合せ回路 | Verilogシミュレーションや論理合成の入力 |

回路JSONは学習用チェックポイントではありません。`run.initial_checkpoint_path` に指定するファイルは `.pth` であり、回路JSONから学習時の重みへ戻す機能はありません。

## 3. 入力は二値化済みのデータを使う

回路へ渡すのは、各要素が0または1の入力です。画像のダウンロード、読み込み、画素値の変換など、データセット側の前処理は生成物に含めません。

現在のMNIST処理では、画素値を0～1のTensorへ変換した後、0より大きい値を1、それ以外を0にします。外部プログラムやハードウェアから回路へ入力するときも、学習時と同じ前処理を行ってください。0～255のグレースケール画像を、そのままC関数やVerilogのポートへ渡すものではありません。

各標本の入力は、元の形状の最後の軸が最も速く変化する順に平坦化します。例えばMNISTの `[1, 28, 28]` は784個の入力に対応します。

- 通常出力のC関数は、標本ごとに並べた `bool` 配列を受け取ります。
- Verilogの `logic_input[i]` は、1標本を平坦化したときの要素 `i` に対応します。
- ライブラリの `Circuit.evaluate()` は、バッチ軸を含むTensorまたはNumPy配列を受け取ります。数値型でも値が厳密に0か1なら使用できますが、閾値処理を自動で行うわけではありません。

Pythonから回路を評価する場合の具体例は、[ライブラリの直接利用](./core-library.md)に記載しています。

## 4. CとVerilogでは出力が異なる

### C：集約後のスコアを返す

生成する関数名は `logicnn_evaluate` です。論理ゲートの計算に続き、回路に記録されたグループ内の加算や、その後のbias・tauによる演算などを実行します。出力配列は、標本ごとに最終出力の値を並べた形式です。

現在のMNISTモデルでは、1標本あたり10個のクラススコアを返します。最大スコアのクラスを選ぶ `argmax` は生成するC関数に含めないため、分類結果が必要な場合は呼び出し側で求めます。

### Verilog：加算前の生ビットを返す

生成するモジュール名は `logicnn_circuit` です。入力ポートは `logic_input`、出力ポートは `logic_output` で、出力するのはクラスごとの加算に使う前の0／1の並びです。

現在のMNISTモデルの違いを整理すると、次のようになります。

| 項目 | 現在のMNISTモデル |
|---|---|
| 入力 | 784ビット |
| Verilog出力 | 最後の論理層の4,000ビット |
| グループ | 400ビットずつ、10グループ |
| C出力 | 各グループの和を8で割った10個のスコア |

この本数は現在のモデル定義に基づく値であり、ライブラリ全体の固定値ではありません。

Verilogには、グループの加算器、bias・tauの数値演算、クラス判定、クロック、リセット、パイプラインレジスタを含めません。FPGA等でそれらが必要になった場合は、生成回路の外側に別途用意します。

### 生ビットの本数と順序を確認する

回路は、簡略化前の生ビットとの対応を保存しています。簡略化で内部の信号IDが変わったり、複数の出力が同じ信号を参照するようになったりしても、外部へ出す本数と順序を保持します。定数0／1になった出力や重複した出力も、その位置から削除しません。

対応を調べるときは、次を確認します。

- JSONの `logical_outputs`：グループ順に並び、各 `node_ids` がグループ内のビット順を表します。
- Verilog内の `group` コメント：各グループの出力開始位置 `offset` と本数 `count` を示します。
- `Circuit.evaluate_logical_outputs()`：Verilogと同じグループ順・ビット順のCPU bool Tensorを返します。

信号IDの大小で出力順を並べ替えないでください。Cのスコアと比較する場合は、Verilogの生ビットを同じグループで加算し、必要な数値演算を行ってから比較します。

## 5. 出力後のコンパイルと評価

通常の `main.py` はソースファイルを保存するところまでです。Cのコンパイル、Verilogのシミュレーション、論理合成、FPGAへの書き込みは自動実行しません。ソース生成だけなら、CコンパイラやVerilogシミュレータは不要です。

CをPythonから呼びたい場合は、ライブラリの `Circuit.compile()` と `evaluate(..., compiled=True)` を使用できます。この操作にはCコンパイラが必要です。詳細は[ライブラリの直接利用](./core-library.md)を参照してください。

論理ビットと整数の集約値は一致を確認し、浮動小数点を含むスコアでは許容誤差を設けて比較します。任意の実行環境で浮動小数点のビット列まで完全一致することを前提にしないでください。

## 6. 対応範囲と失敗時の確認

回路化できるのは、変換処理が対応する論理演算、形状操作、集約後の数値演算です。任意のPyTorchモデルを変換する機能ではありません。2・4・6入力のゲートも対応していますが、LUT方式によって使用できる入力本数が異なります。[LUTと接続の設定](./core-library.md#4-lutと接続を変更する)を確認してください。

C生成では、数値演算の `float16`・`bfloat16` や、浮動小数点から整数への型変換などに未対応の条件があります。生成できない演算を、別の計算へ黙って置き換えることはありません。

出力途中で失敗すると、端末に失敗した段階、保存先、原因と確認事項を表示します。完了済みの学習成果物や回路ファイルは残ります。例えばJSONの保存後にC生成が失敗した場合、JSONは残り、Verilog生成には進みません。

その場合は、残ったファイルだけで3形式すべての出力が成功したと判断せず、エラー内容と生成済みファイルを確認してください。通常設定で同じ学習を再実行する前に、[エラー対応](./troubleshooting.md)も参照してください。

処理の詳細は、[学習後の回路出力](/code-reference/utils/export/circuit_exporter)と[回路API](/code-reference/utils/logicNN_core/src/logicnn_core/circuit/circuit)に記載しています。
