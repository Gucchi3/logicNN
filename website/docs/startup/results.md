# 結果の確認

このページでは、[最小構成での実行](./first-training.md)で保存した結果を確認します。対象は、CPU・1 epoch・回路出力無効で正常終了した実行です。

## 1. 保存先を開く

端末の「学習完了」に表示された保存先を、ファイルエクスプローラーなどで開きます。初回実行用の設定では、プロジェクトルートの `log/` 内に実行ごとのフォルダが作成されます。

```text
log/
└── YYYYMMDD_HHMMSS/
    ├── config.json
    ├── training_info.json
    ├── metrics.jsonl
    ├── curves.png
    ├── model_best.pth
    ├── model_final.pth
    └── test_metrics.json
```

`YYYYMMDD_HHMMSS` は実行開始時の日時です。同じ秒に複数回開始した場合は、末尾に `_01` などの番号が付くため、既存の実行フォルダは上書きされません。今回の設定では `circuit/` が存在しなくても正常です。

## 2. 評価結果を確認する

まず `test_metrics.json` をエディタで開きます。これは、保存済みのbestモデルをテスト用データで評価した結果です。

| 項目 | 意味 | 1 epoch実行で確認する内容 |
|---|---|---|
| `checkpoint` | 評価に使用したチェックポイント | `model_best.pth` |
| `epoch` | bestモデルを保存したepoch | `1` |
| `loss` | テスト用データ全体の平均損失 | 有限の数値が記録されている |
| `accuracy` | テスト用データに対する正解率 | 0～1の割合で記録されている |
| `samples` | 評価した標本数 | `10000` |

JSONの正解率は百分率ではありません。例えば `0.9342` は93.42%を意味します。端末では百分率に変換して表示します。

`validation` は各epochの検証結果、`test` は全学習終了後の最終評価結果です。bestモデルの選択には検証結果を使用し、テスト結果は使用しません。学習中は連続値による演算、検証・テスト時はゲートを選択した離散演算を使用するため、学習精度と検証精度が同じになるとは限りません。

1 epochの実行は動作確認です。精度の値だけで、十分に学習できたかどうかを判断するものではありません。

## 3. 学習履歴とグラフを確認する

`metrics.jsonl` は、1行に1 epoch分のJSONを記録するテキストファイルです。今回の実行では1行になります。

| 項目 | 内容 |
|---|---|
| `epoch` | epoch番号 |
| `learning_rate` | そのepochで使用した学習率 |
| `train_loss` / `validation_loss` | 学習用／検証用データの平均損失 |
| `train_accuracy` / `validation_accuracy` | 学習用／検証用データの正解率。0～1の割合 |

端末ではepoch行の学習率と損失を小数点以下3桁で表示しますが、JSONの記録値はこの表示桁数に丸めません。

`curves.png` を開くと、左側に学習損失と検証損失、右側に赤色の検証精度を表示します。凡例の `latest` は最新epochの値、`best` は記録された最小損失または最高精度です。損失の最良値は、`model_best.pth` の選択基準とは別です。

### 1 epochの場合のグラフ

グラフの線には点のマーカーを付けていません。1 epochだけでは点を結ぶ線分がないため、曲線が見えない場合があります。ファイルの異常ではありません。凡例の数値と `metrics.jsonl` で結果を確認してください。

## 4. 保存済みモデルと実行条件を確認する

| ファイル | 保存する内容 |
|---|---|
| `model_best.pth` | 検証精度が最も高かったepochのモデル状態と構造・学習条件などの情報。同率の場合は先のepochを保持する |
| `model_final.pth` | 最後のepochのモデル状態と関連情報。bestとは別に保存する |
| `config.json` | 今回使用した全設定。保存先などの相対パスは絶対パスに解決した状態で記録する |
| `training_info.json` | 使用したソフトウェアのバージョン、実際のデバイス、モデル構造、データ件数・前処理、最適化の設定など |

1 epochの実行では、bestとfinalは同じepochのモデル状態を保存します。ただし、チェックポイントの種別などが異なるため、同一ファイルではありません。

`.pth` はモデルを読み込むためのファイルであり、テキストエディタで内容を確認する用途には適しません。実行条件を確認する場合は、まずJSONファイルを参照してください。保存済みの重みを次回の初期値として利用できますが、optimizerやschedulerの状態を含む中断再開用の保存ではありません。

## 確認が完了したら

「学習完了」の表示、上記7ファイルの保存、1 epoch分の履歴、10,000件のテスト結果を確認できれば、スタートアップガイドの作業は完了です。

途中でエラーや中断が発生した場合も、一部のファイルが残ることがあります。フォルダが存在することだけで正常終了と判断しないでください。

以後の設定変更や回路出力は [ユーザーガイド](../user-guide/index.md)、関数の実装は [コードリファレンス](../code-reference/index.md) を参照してください。
