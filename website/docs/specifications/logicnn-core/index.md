# logicNN_core 再設計仕様

`logicNN_core` は、torchlogixの機能と実装知識を基礎資料として再設計する、PyTorch向けの汎用論理ゲートニューラルネットワークライブラリである。logicNNアプリケーションの一部として `utils/logicNN_core/` に配置するが、アプリケーション固有の設定、データセット、学習ワークフローおよび成果物管理には依存しない。将来はこのディレクトリだけを独立したPythonパッケージとして配布できる構造にする。

:::warning 文書状態
承認済みの要件・設計に従って段階的に実装・検証している。下記の工程記録は過去からの経過であり、最新状況は [実装・検証記録](./verification.md) を正本とする。判断待ちの範囲は承認済み仕様や実装済み機能と区別する。
:::

## 現在の確認箇所

1. 反映済み: [集約前の出力を保護する規則](./detailed-design.md#96-論理出力を保護する規則)。定数と重複を含め、簡略化・JSON往復・Verilog生成で出力位置を維持する。
2. 反映済み: [承認済みの命名](./detailed-design.md#23-承認済みの命名)。配布名・import名、モデル内で作る `LUTConfig`／`ConnectionConfig`、LUT入力本数 `num_inputs`。
3. 反映済み: [export中の学習切替](./detailed-design.md#82-trainとの関係)。export中の `train(True)` は明示エラーとし、明示解除後に学習へ戻す。
4. C1〜C3完了: 基盤・設定・例外、16論理演算・sampling、Walsh／Light・組合せ・正則化を実装した。全1345テスト合格、CUDA未搭載による7件スキップ。独立配布・ソース品質も合格。詳細は [実装・検証記録](./verification.md) を参照する。
5. 反映済み: [warp正則化の実装保留](./detailed-design.md#174-warp正則化の実装保留承認済み)。補助正則化だけを保留し、指定時は明示エラーとする。Warp方式本体は維持する。
6. [正則化の返却・集約契約](./detailed-design.md#175-正則化の返却集約契約承認済み) は承認済みで、C3のfunctional入口に実装した。層の全level平均はC6／C7で統合する。
7. **C4完了: [Warpの二値評価とLUT抽出の統一](./detailed-design.md#176-warpの二値評価とlut抽出の判定契約承認済み)**。学習式を維持してRaw／Warp／Lightの検証を完了した。全体2286件合格・20件CUDAスキップ、独立レビューで重大な指摘なし。層・回路の統合は後続工程。修正結果と性能の留保は [検証記録](./verification.md#c4追加修正-core-des-007の共通判定表) を参照する。
8. **C5完了: [学習可能接続の旧計算の維持](./detailed-design.md#177-学習可能接続の旧計算との相違承認済み)**。torchlogixと同じく、学習中も候補を1本選び旧独自勾配を用いる。固定／学習可能Denseと固定Convを実装した。
9. **C6・C7完了: 論理層と集約**。Dense、2D／3D Conv、OR pooling、GroupSum、入力勾配倍率、bool export、保存復元を統合した。全体3154件合格・31件CUDAスキップ。C／Verilog出力まで完成したことを意味しない。
10. **C8完了: [学習可能二値化の閾値](./detailed-design.md#178-学習可能二値化の閾値の不一致旧方式の維持を承認)**。共通閾値案は採用せず、torchlogixと同じtrainのsoftplus・evalのraw cumsumを維持する。評価時の昇順は保証しない。二値化全方式、Residual、共有moduleのexport切替を実装し、全体3429件合格・36件CUDAスキップ。次はC9の回路構築である。
11. **承認済み・C9再開: [回路の入力境界と外部FXの出力情報](./detailed-design.md#179-c9開始前の入力境界と外部fxの出力情報承認済み)**。C・Verilogとも二値化済み0／1入力とし、前処理は生成しない。外部FXは元の出力対応情報を必須にし、通常モデル変換では自動記録する。
12. **C9完了: [集約計算と途中丸め](./detailed-design.md#1710-c9の集約計算と途中丸め承認済み)**。式を係数へまとめず、元の演算順序・数値型・scalarの形態を回路データへ保持する。既知の反例を修正し、全体3982件合格・36件CUDAスキップ。C／Verilog生成はまだ未実装。
13. **承認済み: [実行APIの返却形式](./detailed-design.md#1711-c10の実行apiの返却形式承認済み)**。Python実行／C実行ともCPU Tensor返却とbatch形状を統一する。学習・通常のモデル実行のdeviceは変更しない。回路実行・JSON・簡略化を実装し、Cコード生成は後続で統合する。
14. **承認済み: [浮動小数点一致基準](./detailed-design.md#1712-c10の浮動小数点一致基準承認済み)**。0／1と整数の完全一致を維持し、小数は演算順序・型を保った微小な丸め差を許容する。完全一致のためにコードを複雑化せず、他の計算も適用できる範囲に限定する。
15. **C10完了: [CPU回路実行・公開API統合](./verification.md#c10完了-cpu回路実行公開api統合)**。公開CPU実行・JSON保存復元・出力を保護する簡略化を統合した。
16. **現在地: [学習済みモデルのCとVerilog実検証](./verification.md#学習済みモデルのcとverilog実検証)**。C生成・compiled実行・Verilog生成、アプリ学習と成果物保存を接続し、学習済みMNISTLGNでPython／C／Verilogを比較した。Alkaid・一部参照モデル・最終受入は未完であり、全体の完成ではない。

## 外側のlogicNNとの関係

| 領域 | 担当 |
|---|---|
| `utils/logicNN_core/` | 論理演算、LUT、接続、論理層、回路IR、簡略化、C／Verilog出力 |
| `model/` | `logicNN_core` の公開層を組み合わせた具体的なモデル構造 |
| `utils/data/` | データセット取得、分割、前処理、二値化 |
| `utils/trainer/` | 学習・検証・テストの実行順序と最適化方式 |
| `utils/export/` | logicNN成果物としての保存先とファイル名の管理 |

`logicNN_core` はMNISTを知らない。MNISTLGNは最初の利用例かつ受入対象だが、ライブラリのAPIや形状制約をMNISTへ固定しない。

## 再設計の原則

- torchlogixのソースを外部ライブラリとしてそのまま呼び出さない。
- 数学的意味と有用な機能は可能な限り維持する。
- 巨大な単一ファイルを責務別に分割する。
- 公開APIと内部実装を分離し、内部ファイル配置を変更しても利用側を壊しにくくする。
- データセット固有モデルは汎用コアへ混在させず、参照モデルとして残す。
- コピーまたは実質的に派生したコードにはMITライセンスと原著作者表示を残す。

## 文書の正本

logicNNアプリケーション全体の要件は一階層上の仕様書を正本とする。論理ゲートNNの数学、公開API、回路IRおよびエクスポート機能は本セクションを正本とする。同じ定義を両方へ複製せず、アプリケーション仕様から本セクションへリンクする。
